## 关键决策

### 保留 React/Vite，不在同一轮迁移 Next.js

问题：框架迁移和视觉重构同时进行会扩大认证恢复、路由守卫、Nginx fallback 和部署配置的回归面。

原因：当前 React/Vite 架构已经具备路由、状态、测试和容器交付能力，本轮目标是提升使用体验，不是改变渲染模型。

修改建议：先在现有架构完成设计系统和页面结构收敛；只有出现 SSR、SEO、服务端组件或多应用路由等明确需求时再评估 Next.js。

示例：登录、注册、资料、改密和权限 API 调用保持原实现，仅替换布局与表现层。

### 业务后台采用克制的工作台布局

问题：认证与 RBAC 工具需要高频扫描和重复操作，不适合营销页式大标题与装饰性卡片。

原因：目标用户更关注账号状态、角色、权限和操作结果。

修改建议：使用固定导航、紧凑标题、清晰表格和有限强调色；卡片只用于真正独立的数据或操作单元。

示例：权限页将角色表、角色分配和权限表分开，并通过方法标签区分只读与变更接口。

## 边界与后续

- 本轮没有引入 Next.js、Ant Design 或新的状态库，避免为了视觉升级扩大技术栈。
- 视觉检查覆盖代表性桌面与移动视口，不等于完整的 WCAG 审计；后续可补键盘遍历、对比度和屏幕阅读器检查。
- 管理员角色分配仍以用户 ID 为输入；稳定版前应增加用户搜索和列表工作流。
- 新界面保持现有 API 与权限契约，后端仍是认证和授权的最终安全边界。
